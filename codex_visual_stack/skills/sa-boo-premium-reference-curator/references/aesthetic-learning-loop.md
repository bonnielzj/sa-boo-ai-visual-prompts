# 审美积累与认可结果学习 / Aesthetic learning loop

审美积累的目的，是把已经有效的设计手法、风格机制和工作方法变成下一次可直接调用的持久知识，减少重复推导与试错，而不是在每个设计任务开始前增加一次检索、研究或 QA。它记录可核对、可修正的设计证据；不训练模型权重，不凭单次结果自动建立永久用户画像，也不取代当前 brief。

## 1. 先做结果，按需唤回经验

当前明确指令、指定素材和最新修正始终优先。按任务实际需要选择检索深度：

- **清楚的局部修改：**直接改当前指定资产，不检索审美历史，不建立参考库。
- **同项目／同系列延展：**只调取当前认可母稿、最新相关修正和一个真正影响本轮的经验。
- **新的视觉方向或明显卡住：**调取少量同类正例与反例，通常不超过解决当前问题所需的三至五项。
- **明确要求审美研究、找参考或建库：**再调用 Curator／Asset Index 的完整流程。

不要为了“先确认审美”而延迟第一个可查看结果。已经有清楚参考时，参考本身就是当前工作基准。

## 2. 认可证据的状态

把反馈绑定到具体资产、版本和 Bonnie 的原话，使用以下状态，不能互相替代：

- `USER_ACCEPTED_RESULT`：明确认可整个当前结果，例如对完整结果说“很好”“就这个”“可以保留”。
- `USER_ACCEPTED_DIMENSION`：只认可概念、字体、色彩、版式、材质、局部或其他明确维度。
- `USER_SELECTED_FOR_DEVELOPMENT`：选择这个方向继续推进；不等于所有细节已经认可。
- `TECHNICALLY_VERIFIED`：技术正确、文件可用或 QA 通过；不等于审美认可。
- `REVIEW_PENDING`：继续对话、未评价或沉默；不视为认可。
- `DESIGNER_HYPOTHESIS`：设计师对“为什么有效”的推断，不是 Bonnie 已声明的偏好。

“很好／可以／保留”的范围由当时展示对象和句子指向决定。反馈只指向一个局部时，不升级成整稿认可；只说“继续这个方向”时，记录为继续发展而不是完成批准。

## 3. 从认可结果中提炼，而不是只存一句好评

收到有意义的认可、选择或否定后，用一个短循环总结：

1. **绑定证据：**记录准确资产／版本、反馈原话和反馈所指范围。
2. **比较变化：**与 brief、前一版或被替代方案比较，找出真正改变了什么。
3. **提炼机制：**写清可见关系、它产生的作用、下次能采取的动作；避免只写“高级”“有感觉”“喜欢这种风格”。
4. **区分事实与推断：**Bonnie 没说明原因时，认可事实照实保存；原因标为 `DESIGNER_HYPOTHESIS`，无需为了补齐记录追问。
5. **改变下一步：**保留已经被认可的部分，减少已证明无效的绕路，并让同项目下一版优先沿用有效机制。

可复用记录采用：

```text
资产／版本 + 用户原话
状态 + 认可或否定的具体维度
可见变化 → 作用机制 → 下次动作
适用范围 + 不适用条件
推断项（如有）：DESIGNER_HYPOTHESIS
```

只有能改变下一次参考选择、构图、造型、字体、材料、编辑方法或淘汰决定的内容才值得记录。

## 4. 审美学习与工作流学习分开

- **审美学习：**什么视觉关系、比例、节奏、层级、字形、色彩、材质或叙事成立。
- **工作流学习：**什么输入、工具、先后顺序、预览方式或修改粒度更快地得到可用结果。

“很好看”主要支持审美证据；“这样快很多／这次直接对了”主要支持工作流证据。一次反馈可能同时包含两者，但不要把效率认可误写成审美偏好，也不要把审美认可误写成某个软件或制作方法的永久要求。

## 5. 复用范围与升级门槛

复用优先级：

1. 当前 brief 与最新明确修正；
2. 当前项目已认可母稿和维度；
3. 同系列、同品类的重复证据；
4. 跨项目可迁移机制；
5. 设计师假设、趋势和模型记忆。

同项目可直接复用被认可的元素。跨项目只转移机制与判断方法，不自动转移 Logo、配色、图案、内容、构图或完整风格。一次认可不升级为“Bonnie 一向喜欢”；只有重复证据或 Bonnie 的明确确认，才可形成跨项目原则。

新的明确反馈优先于旧记录。旧结论保留来源并标明被替代，不能让过期偏好继续控制当前结果。

## 6. 资产与记录的边界

认可结果本身通常是最有价值的审美资产。优先保留可查看的结果、可编辑母稿、必要局部和版本关系；不要为普通任务另建数据库、contact sheet、manifest、hash 或 QA 报告。

持久积累使用分层存放：

1. **项目／系列层：**具体母稿、风格状态、当前有效手法和最新修正；下一次同项目优先调用。
2. **领域 skill 层：**反复有效的设计方法、制作路径、判断逻辑或工具路由；用于同类任务，不携带项目身份。
3. **跨项目偏好层：**只有重复证据或 Bonnie 明确确认的稳定倾向；仍须服从新 brief。

有现成记录时做最小增量更新，不重复建立平行档案。一次普通认可若不会改变后续选择，可以只保留在当前版本关系中；当方法会在未来复用，或成功／失败暴露了 skill 的错误路由，就应修正对应记录或 skill，而不是等到下次重新梳理。正式参考库、长期索引和批量采集仍只在 Bonnie 明确要求时执行。

Bonnie 已明确要求把有用的设计方法、风格机制和工作逻辑持续内化为信息数据库。此授权用于有边界的持久学习与 skill 修正，不授权后台采集、公开分享、跨品牌使用私有资产，也不要求把每一次反馈都写成全局偏好。

## 7. 交付前的审美检查

在观看尺度检查整体视觉事件，而不是只检查图层或技术完整性：

- 核心概念是否清楚，层级、节奏、比例、留白和视线是否成立；
- 字体、图像、材质和装饰是否共同服务同一个表达；
- 是否保留已认可部分，并只改变本轮要求改变的内容；
- 是否出现明显低级错误或与 brief、参考严重偏离。

检查应简短、内部完成。发现问题就直接修正；没有会改变下一步的风险时，不生成可见 QA 报告。
